One workflow, from intent to evidence.

Start a project, clarify what it must do, then inspect the work and its proof. Your team keeps the decision.

02 · Assemble

Build a contained starting point

03 · Inspect

See the project and its proof

Factory Studio and Graph Ops present requirements, gates, evidence and blocked work in one local, read-only view.

04 · Decide

Keep approval with people

FactoryLine connects work to evidence and the next fact-derived action. A completed task or a green check is not automatic permission to release.

First Proof uses a generated local sandbox. It checks the demonstration, not your repository. For real work, define the scope and checks before running an audit.

Release status, examples and limits

Current coverage: Go/Java/C#/Ruby framework sources and sinks plus wider Ruby/Swift trust checks. New request rules are review-tier; the shipped variant has no fresh precision score. Inspect coverage evidence.

Historical strengths and gaps. Round 7, the earlier ruleset, supported 38/40 decided default-tier alerts (95%; Wilson 83.5–98.6%), with 12 additional unclear. Review tier: 23/40 (57.5%), plus 3 unclear. Advisory recall: 0/161. Six languages had insufficient precision samples; AI labels are not twelve-language accuracy or independent human validation. Inspect per-language results and limits.

Seeded finding example: sample tenant-read inputs illustrate a finding and repaired case. This is not a live scan, tenant-isolation proof, accuracy benchmark or independent review. Candidate CI verification and human review are still required.

Core 0.50.1 addresses Stripe credential and MD5 detection. VS Marketplace lists the 1.3.6 VSIX. JetBrains accepted the 1.3.6 submission for review. See release channels. PR 354 adds the bounded Proof Agent, signed execution-observation checks and Devin evidence profile.

The Proof Agent runs a human-approved signed plan and records evidence for review. It does not approve its result. Signed-observation checks establish the declared observation binding, not code correctness or release readiness. Local tests do not establish marketplace availability or live provider compatibility.

Audit depth depends on language, project policy and supplied evidence. The default static scan analyzes Python. Other native analysis requires configured workers. Check the result status and audited file count, even when the command exits 0. Static inventory is not runtime proof. This is a static preview, not a hosted repository scanner.
