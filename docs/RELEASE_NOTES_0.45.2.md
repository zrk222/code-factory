# Code Factory 0.45.2 — start the AppForge evidence path without the ceremony

AppForge now begins with one small, honest step: state the user’s app mission
and the exact build you want reviewed. `factory revenue appforge-init` writes a
local workspace with the candidate, user design input, a starter storyboard
brief, and the next safe action.

Then `factory revenue evidence-kit` prepares the candidate-bound worklist and
templates for the four evidence lanes. It asks for ten real iPhone journeys and
three real 13-inch iPad journeys so teams do not discover missing media and
journey coverage at the end.

Templates are intentionally non-passing. They cannot become an Apple-ready
claim until the real App Review, Store media, SaaS, and strict quality-audit
receipts are collected for that exact candidate. No command in this release
accesses credentials, runs a device, uploads, submits to Apple, or claims App
Review approval.

See [AppForge Evidence Kit](APPFORGE_EVIDENCE_KIT.md) and
[Submission Assurance](APPFORGE_SUBMISSION_ASSURANCE.md).
