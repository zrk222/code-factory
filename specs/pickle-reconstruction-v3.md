# Spec: pickle-reconstruction-v3
Status: approved
SpecFactor-target: 0.75–2.5

## MUST — Functional core
### Description
Resolve pickle findings using independently regenerated byte origin and typed reconstruction evidence. This packet adds a versioned model for captured Exception records containing canonical IntEnum members. The complete pickle-family objective remains open for unsupported reducers, state hooks, drivers and IPC; this packet does not redefine completion around one case.

### Requirements (EARS)
- When `PICKLE_GRAPH_SELECTED` requests typed-pickle-reconstruction-v3, the system shall emit exactly 1 selected source-bound contract from trusted-dependencies-v2 and emit 0 behavioral changes for source-closed-v1 and both prior exception models. [R1]
- When `PICKLE_GRAPH_ORIGIN` consumes direct nested or single-block named dump bytes, the system shall bind the canonical dump and load, reject global or nonlocal payload storage and any payload alias, overwrite or escape, and emit 0 safety decisions from byte provenance alone. [R2]
- When `PICKLE_GRAPH_RECONSTRUCTED` receives a captured IntEnum member, the system shall emit a lookup recipe bound to the exact class, export chain, literal member and CPython enum runtime artifacts within 8 classes and 512 evidence states. [R3]
- When `PICKLE_GRAPH_UNSUPPORTED` encounters custom reducers, state hooks, descriptors, metaclasses, dynamic bases, unresolved graph leaves, cycles or provider mutation, the system shall emit the original finding with 0 negative decisions. [R4]
- When `PICKLE_GRAPH_ADMITTED` evaluates a negative candidate, the system shall validate regenerated model, runtime, contract, source, origin and reconstruction identities from current captured bytes within 64 artifacts and 1000000 bytes per artifact. [R5]
- When `PICKLE_GRAPH_MEASURED` runs the exposed family, the system shall emit outcomes for all 37 original claims, retain all 2 true positives and all 2 unclear cases, and emit false-positive removals and remaining counts separately with 0 fresh-held-out claims. [R6]
- When `PICKLE_GRAPH_QUALIFIED` completes, the system shall add 0 production modules, 0 dependencies and 0 target executions, and record focused tests, independent review and hash-bound measurement evidence. [R7]

### Acceptance criteria (Gherkin)
```gherkin
Scenario: Typed reconstruction is selected independently
  Given PICKLE_GRAPH_SELECTED has an unambiguous captured contract
  When PICKLE_GRAPH_RECONSTRUCTED runs
  Then R1 and R3 bind one model and the canonical enum recipe

Scenario: Byte origin does not excuse unknown reconstruction
  Given PICKLE_GRAPH_ORIGIN has canonical local dump bytes
  When PICKLE_GRAPH_UNSUPPORTED encounters a custom reducer
  Then R2 and R4 retain the original finding

Scenario: Admission rejects stale authority
  Given PICKLE_GRAPH_SELECTED has changed captured bytes
  When PICKLE_GRAPH_ADMITTED runs
  Then R5 regenerates the identity and rejects the stale candidate

Scenario: The full family remains the measurement unit
  Given PICKLE_GRAPH_MEASURED contains 37 original claims
  When PICKLE_GRAPH_QUALIFIED finishes
  Then R6 preserves the controls and R7 records zero target executions
```

## SHOULD — Technical/structural
- Keep the existing contract-set profile and wire schema. Version the model and bind extra enum runtime identities only for that descriptor. Existing contracts continue using their unchanged runtime identities.
- Resolve captured reexports with a bounded, cycle-rejecting import walk. Never import or execute a target. A declaration alone is not authority for a dynamic module export.
- Preserve the enum type and member as a typed graph node; replacing it with its integer value does not prove equivalent reconstruction.
- Reject mutated cached globals, import/audit hooks, extension registries, pickle dispatch changes, payload aliases and unknown object leaves. Old models retain their existing origin/reconstruction grammar.
- Keep original diagnostics, labels and severities. An unsupported case is unresolved, not safe; missing coverage is not a zero-alert result.

## SHOULD NOT — Implementation details
- Do not exempt tests, repositories or package names, and do not infer safety from a successful roundtrip.
- Do not promote selective policy precision or one qualified fixture into a family-wide accuracy claim.
