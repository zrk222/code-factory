# Spec: perf-optimization-appforge-revenueforge-prestige
Status: draft
SpecFactor-target: 0.75–2.5

## MUST — Functional core
### Description
Reduce repeat-run CPU and filesystem work in AppForge and RevenueForge artifact
generation and in Prestige's text-based purpose scoring, while preserving output
bytes, safety gates, scores, and recommendation ordering.

### User roles
- AppForge and RevenueForge users rerunning deterministic local generation.
- Developers using Prestige scoring on large HTML pages.

### Requirements (EARS)
<!-- Every requirement uses an EARS keyword: shall / When / While / If / Where -->
- The system shall emit each artifact from the reference renderer and preserve
  identical file content for repeated unchanged inputs.
- If output content differs, then the system shall emit the changed output
  through the existing atomic file-replacement routine.
- The system shall return the same purpose-term counts as the current Unicode
  word-boundary matcher for all supported purpose profiles.
- The system shall return identical receipt fields, output hashes, and score
  values while optimizing the selected repeated-generation and scoring paths.

### Acceptance criteria (Gherkin)
```gherkin
Scenario: repeat AppForge and RevenueForge generation
  Given a valid input and a previously generated output directory
  When generation runs again without input changes
  Then generated bytes and receipts remain equal and unchanged files are not replaced

Scenario: changed generated output
  Given a valid input whose content changes
  When generation runs into the existing output directory
  Then changed files are replaced and their receipt or manifest verifies

Scenario: Prestige purpose score parity
  Given a page and purpose vocabulary containing overlaps and Unicode text
  When the optimized term matcher runs
  Then every term-presence count and complete score result match the reference matcher
```
